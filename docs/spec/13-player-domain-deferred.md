## 1. 이 문서의 경계

라운드 루프 · 페이즈 타이밍 · `rounds`/`avatarRequests` 문서 구조 · 화면 구성은 **아바타 개선으로 바뀐다.** 여기 적지 않는다.

**아래는 아바타 개선이 어떻게 끝나든 바뀌지 않는다.** 지금 확정할 수 있고, 확정해두지 않으면 A2 착수 시점에 차단 등급이 된다.

---

## 2. 지금 못박는 것 — 배당 규약 (`DR-81`)

**규약 함정.** `shared/game-engine.js:14`의 값은 *배당비*가 아니라 **원금 포함 반환 배수**다.

```js
const PAYOUT = { player: 2.0, banker: 1.95, tie: 9.0, playerPair: 12.0, bankerPair: 12.0 };
```

| 화면 표기 | 상수 | 뜻 |
|---|---|---|
| `1:1` | `2.0` | 원금 + 동액 |
| `0.95:1` | `1.95` | 원금 + 0.95배 (**뱅커 5% 커미션이 접혀 있다**) |
| `8:1` | `9.0` | 원금 + 8배 |
| `11:1` | `12.0` | 원금 + 11배 |

**혼동하면 지급액이 정확히 2배 또는 절반이 된다.** `shareRate` %→bp 함정([`10`](10-partner-console.md) `R-10-43`)과 같은 계열이다.

| ID | 요구사항 | AC |
|---|---|---|
| `R-13-01` | [`04` §13](../architecture/04-posting-rules.md)에 **"이 값은 원금 포함 반환 배수이며 배당비가 아니다"** 가 한 줄로 있다. **표 내용은 A1과 함께 움직여도 이 한 줄은 지금 쓸 수 있다** | `AC-81-1` |
| `R-13-02` | `game` 스키마에 배당표가 있다 — 게임 종류 × 베팅 종류 → 배수 + 커미션율 | `AC-81-2` |
| `R-13-03` | `op_payout`이 **클라이언트가 보낸 금액이 아니라 이 표에서 계산**한다 | `AC-81-3` |
| `R-13-04` | **뱅커 커미션을 별도 분개로 뺀다** (결정 §10). 배수에 접어두지 않는다 — 커미션 수익을 따로 보려면 지금 정해야 한다. `commission_expense`는 롤링·쉐어용 **차변** 계정이라 이 자리에 쓸 수 없으므로 **수입 계정을 새로 만든다** | `AC-81-4` |
| `R-13-05` | 배수 ↔ 배당비 왕복 테스트가 있다 | `AC-81-5`·`AC-77-4` |

## 3. 지금 못박는 것 — 페이아웃 멱등키 (`DR-78`)

**문제**: [`04` §13](../architecture/04-posting-rules.md)이 베팅 표와 페이아웃 표를 나란히 놓고 **멱등키를 한 줄만** 준다 — `bet:{round_id}:{member_code}:{bet_type}`. 멱등키 공간이 전역이라 둘이 충돌한다. 페이아웃이 이 키를 쓰면 `begin_idempotent()`가 베팅 행을 찾고 지문이 달라 **422로 거절한다.** 키를 비우면 `ddl/008`이 필수라며 거절한다. **두 경로 모두 지급이 불가능하다.**

무승부 푸시가 이 문제를 매 라운드로 끌어올린다 — 타이일 때 `mult = 1`이므로 **원금과 같은 금액의 페이아웃 분개**가 발생하고, 금액까지 같아 사람 눈으로도 중복으로 보인다.

| ID | 요구사항 | AC |
|---|---|---|
| `R-13-10` | 페이아웃 멱등키가 `payout:{round_id}:{member_code}:{bet_type}`로 분리돼 있다 | `AC-78-1` |
| `R-13-11` | 라운드 취소·정정 키도 **같은 접두사 규칙으로 미리 예약**돼 있다 | `AC-78-2` |
| `R-13-12` | [`04` §13](../architecture/04-posting-rules.md)의 각 하위 연산이 **자기 멱등키를 갖는다** — §13-2가 이미 그렇게 하고 있다. §13만 하나였다 | `AC-78-4` |
| `R-13-13` | 접두사가 [`03`](03-api-idempotency.md) §4 대장에 등재돼 있다 | — |

> **이 절은 보류 대상이 아니다.** [`04`](../architecture/04-posting-rules.md)의 보류 선언은 *"13절의 나머지(라운드 취소 · 결과 정정 · 팁 · 가입 보너스)"* 로 범위를 명시한다. 베팅·페이아웃 두 표는 확정분이며 **A2 착수 시점에는 차단 등급이다.**

## 4. 지금 못박는 것 — 거래 행위자 모델 (`DR-79`)

**문제**: `transactions`의 행위자는 **직원뿐**이고 `auth_method`에 회원 인증을 표현할 값이 없다.

- 스피드 자가 베팅은 회원 본인이 행위자인데 `auth_method='system'` + 행위자 NULL이 되어 **누가 걸었는지 사라진다.**
- 아바타 대리 베팅은 지시자(회원)와 집행자(직원)가 분리된 구조인데 **행위자 칸이 하나뿐이라 둘 중 하나만 남는다** — "직원이 회원 돈으로 건 베팅"의 책임 추적이 성립하지 않는다.

**케이지 측 4-eyes가 지키려는 것과 정확히 같은 종류의 위험인데 장치가 없다.**

| ID | 요구사항 | AC |
|---|---|---|
| `R-13-20` | `auth_method`에 회원 인증 값이 있다 | `AC-79-1` |
| `R-13-21` | 행위자가 일반화됐다 — `actor_party_id`로 바꾸거나 `on_behalf_of_party_id`를 더한 **2행 모델**. 대리 베팅에서 지시자와 집행자가 **둘 다** 남는다 | `AC-79-2` |
| `R-13-22` | `tx_actor_required` CHECK가 재작성됐다 | `AC-79-3` |
| `R-13-23` | 감사 조회 뷰가 `identity.staff`만 LEFT JOIN하던 것을 함께 고쳤다 | `AC-79-4` |
| `R-13-24` | `DR-75`와 **함께** 해소됐다 — 저쪽은 주체가 없다는 것이고 이쪽은 주체가 생겨도 거래가 그를 가리킬 수 없다는 것이다 | `AC-79-5` |

> **이 공백도 보류 밖이다.** `ddl/002`와 `ddl/004`는 [`00` §8](../architecture/00-system-map.md)에서 ✅ 완료다. A1이 정하는 것은 `game` 스키마이지 `transactions`의 행위자 컬럼이 아니다. **아바타 개선이 어떻게 끝나든 이 두 컬럼은 바뀌지 않는다.**
