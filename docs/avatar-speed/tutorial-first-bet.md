# 튜토리얼 — 첫 베팅부터 원장 확인까지

> **분류**: Tutorial (학습 지향)
> **소요 시간**: 약 15분
> **작성 기준일**: 2026-08-15 · 브랜치 `backend`
> **관련 문서**: [처리 흐름](explanation-round-flow.md) · [룰과 로드맵](explanation-rules-roadmaps.md)

이 튜토리얼을 마치면 스피드 테이블에서 직접 칩을 놓아 베팅하고, 결과를 받고, 그 베팅이
Firestore에 실제 문서로 남는 것까지 눈으로 확인하게 됩니다. 로드맵(로드) 보드가 어떻게 채워지는지,
아바타 모드가 무엇이 다른지도 함께 보게 됩니다.

**3단계 안에 첫 결과를 봅니다.** 설정은 최소한만 합니다.

## 필요한 것

- Node.js와 [Firebase CLI](https://firebase.google.com/docs/cli) (`npm install -g firebase-tools`)
- 이 저장소를 클론한 로컬 사본
- 최신 브라우저 (Chrome, Edge, Firefox 아무거나)

Firebase 프로젝트 접근 권한이 있다면 배포된 사이트로 진행해도 됩니다. 그 경우 1단계를 건너뛰고
2단계부터 시작하세요.

---

## 1단계: 앱 띄우기

저장소 루트에서 실행합니다.

```bash
firebase emulators:start --only hosting
```

```
✔  hosting: Local server: http://localhost:5000
```

브라우저에서 `http://localhost:5000/partner-admin/`을 엽니다. 파트너 어드민 로그인 화면이 뜹니다.

> 빌드 단계가 없습니다. 이 저장소는 프레임워크와 번들러 없이 HTML/CSS/브라우저 JS와 Firebase
> compat SDK만 쓰므로, 파일을 그대로 서빙하면 바로 실행됩니다.

---

## 2단계: 데모 데이터 만들기

빈 Firestore에는 테이블도 회원도 없어서 로비가 비어 있습니다. 한 번에 채웁니다.

1. 파트너 어드민에 `admin` / `0000`으로 로그인합니다.
2. 상단의 **데모 데이터 생성** 버튼을 누릅니다.
3. 확인 대화상자에서 계속을 누릅니다.

```
데모 데이터 생성 중...
데모 데이터 생성 완료 (회원 12명, 라운드 250개)
```

방금 생성된 것:

| 컬렉션 | 내용 |
| --- | --- |
| `members` | 회원 여러 명 (비밀번호 전부 `0000`) |
| `tables` | 아바타·스피드 테이블 (`status: 'open'`) |
| `rounds` | 테이블당 25라운드의 과거 결과 |
| `memberLedger` | 입출금·베팅·배당·포인트 항목 |
| `chatMessages` | 아바타 테이블 채팅 40건 |
| 그 외 | 공지, 문의, 이벤트, 로그 등 |

**회원 ID 하나를 메모해 두세요.** 좌측 메뉴 **회원 관리**(또는 유저리스트)에서 아무 ID나
복사하면 됩니다. `SE`로 시작하는 형태입니다.

---

## 3단계: 플레이어로 로그인하고 첫 결과 보기

새 탭에서 `http://localhost:5000/avatar/`를 엽니다.

1. **아이디**에 방금 복사한 회원 ID를, **비밀번호**에 `0000`을 입력합니다.
2. **로그인**을 누릅니다.
3. 게임 선택 화면에서 **스피드 (SPEED)** 카드를 클릭합니다.

스피드 로비가 열리고 테이블 카드들이 보입니다. **여기서 이미 라운드가 돌고 있습니다.**

각 카드에서 확인하세요:

- 상태 줄의 `⏱` 타이머가 15초부터 카운트다운합니다.
- 카드마다 카운트다운 숫자가 다릅니다. 3초씩 어긋나게 시작하도록 설계되어 있어 실제 카지노
  플로어처럼 결과가 흩어져 나옵니다.
- 15초 뒤 딜링이 시작되고, 3초 뒤 `P7 : B3` 같은 점수가 타이머 옆에 나타납니다.
- 결과가 나오는 순간 카드 하단의 미니 로드에 동그라미가 하나 추가됩니다.
- 같은 편이 3연속 이기면 🔥 배지가 붙습니다.

**여기까지가 첫 결과입니다.** 아무것도 설정하지 않고 게임이 돌아가는 것을 봤습니다.

> **목록에서는 베팅할 수 없습니다.** 예전에는 카드에 P/T/B 스팟이 있었지만 지금은
> 테이블을 열어야 베팅할 수 있습니다. 목록은 "어느 테이블에 들어갈지" 고르는 화면입니다.

---

## 4단계: 테이블에 들어가서 첫 베팅 놓기

아무 카드나 클릭합니다. 전체 화면 테이블 뷰가 열립니다.

### 화면 구성

| 영역 | 내용 |
| --- | --- |
| 좌측 스테이지 | 라이브 화면 · `SPEED` 배지 · 테이블명 · 한도 · 단계 배너 · 카드 · 타이머 링 |
| 중앙 스코어보드 | P/B/T 승수 + 페어 횟수 · 비드 플레이트 · 빅로드 · 파생 로드 3종 |
| 우측 베팅 패널 | 베팅 스팟 5개 + 칩 트레이 |

### 베팅 스팟 5개

| 스팟 | 배당 | 승리 조건 |
| --- | --- | --- |
| 플레이어 페어 | 11:1 | 플레이어 **처음 두 장**의 랭크가 같음 |
| 타이 | 8:1 | 무승부 |
| 뱅커 페어 | 11:1 | 뱅커 처음 두 장의 랭크가 같음 |
| 플레이어 | 1:1 | 플레이어 점수가 높음 |
| 뱅커 | 0.95:1 | 뱅커 점수가 높음 |

### 걸어 보기

칩 트레이가 베팅 패널 하단에 있습니다: `5천` `1만` `5만` `10만` `50만` `1M`.

1. **`1만` 칩을 클릭**합니다. 선택된 칩이 위로 튀어오르고 금색 테두리가 생깁니다.
2. 단계 배너가 `베팅중`이고 타이머가 5초 이상 남았는지 확인합니다.
3. **뱅커 스팟을 클릭**합니다.

일어나는 일:

- 스팟에 `10,000`이 표시되고 테두리가 강조됩니다.
- **헤더의 보유금이 10,000 줄어듭니다.**

> 이 시점에는 아직 Firestore에 아무것도 쓰이지 않았습니다. 헤더 숫자는 `projectSpeedBalance()`가
> "미확정 베팅을 뺀 사용 가능 금액"을 계산해 보여주는 것입니다. 실제 원장 쓰기는 딜링 단계에
> 일어납니다.

한 번 더 클릭하면 20,000이 됩니다. 칩을 쌓는 방식입니다.

**`5천` 칩을 골라 플레이어 페어에도 걸어 보세요.** 페어는 자주 나오지 않지만 나오면 11배입니다.
P/B/T 결과와 무관하게 정산되므로, 뱅커가 이기면서 플레이어 페어가 뜨는 라운드도 있습니다.

> **"베팅완료" 버튼은 아무것도 하지 않습니다.** 토스트만 뜹니다. 베팅은 스팟을 클릭하는 순간
> 이미 반영되어 있고, 베팅 단계가 끝날 때까지 "취소"로 전부 되돌릴 수 있습니다 —
> [G-12](explanation-known-gaps.md#g-12--베팅완료-버튼이-아무것도-확정하지-않는다) 참고.

## 5단계: 결과 확인

타이머가 0이 되기를 기다립니다.

**딜링 단계 (3초)** — 스팟이 잠기고 더 이상 클릭이 받아들여지지 않습니다. 이 순간
`memberLedger`에 `category: 'bet'`, `amount: -10000` 문서가 쓰입니다.

카드가 **P1 → B1 → P2 → B2** 순서로 260ms 간격으로 놓입니다. 여기서 끝나지 않는 라운드가
있습니다 — 두 핸드 점수에 따라 **플레이어 서드카드, 뱅커 서드카드가 이어서 놓입니다.**

```
♠7 ♥K  →  플레이어 7점, 스탠드
♦3 ♣A  →  뱅커 4점 · 플레이어가 안 받았으므로 뱅커도 0~5면 드로우 → 서드카드 1장
```

**서드카드가 나오는 라운드를 한 번 지켜보세요.** 실제 바카라의 푼토 반코 타블로가 그대로
구현되어 있습니다 — 아무도 선택하지 않고 점수만으로 결정됩니다
([룰과 로드맵](explanation-rules-roadmaps.md#서드카드-룰-푼토-반코-타블로) 참고).

**결과 단계 (3초)** — 세 가지 중 하나입니다.

| 결과 | 뱅커에 10,000을 걸었다면 |
| --- | --- |
| `BANKER WIN` | 19,500 지급 (`10000 × 1.95`). 토스트로 금액 표시 |
| `PLAYER WIN` | 아무것도 없음. 10,000 손실 |
| `TIE` | 10,000 반환 (푸시). 손익 0 |

배당은 총 반환 배수입니다. 뱅커 1.95배는 원금 포함이므로 순이익은 9,500원 — 5% 커미션이 배수에
녹아 있습니다.

빅로드에 결과가 하나 추가되고, 좌측 P/B/T 집계 숫자 중 하나가 올라갑니다.

**"반복" 버튼** — 직전 라운드와 같은 베팅을 한 번에 재현합니다. 다음 라운드 베팅 단계에서
눌러 보세요.

## 6단계: 로드맵 읽고 다중 테이블 확인하기

### 스코어보드 배치

실제 카지노 모니터와 같은 배치입니다.

```
┌──────────────────────┬─────────────────────────────┐
│ P/B/T 승수 + 페어 횟수  │  빅로드 (대로)        6행     │
│                      ├─────────────────────────────┤
│ 비드 플레이트 (육매)    │  대안목 (빅아이)      3행     │
│ 최근 40개             ├─────────────────────────────┤
│                      │  소로 (스몰로드)      3행     │
│                      ├─────────────────────────────┤
│                      │  갑충로 (카카로치)    3행     │
└──────────────────────┴─────────────────────────────┘
```

### 로드맵 읽는 법

**비드 플레이트**(좌측 아래) — 같은 결과가 연속되면 세로로 쌓이고, 결과가 바뀌면 새 열이
시작됩니다. 한 열에는 P/B/T 중 한 종류만 들어갑니다. 글자가 그대로 찍혀 있어 타이도
자기 열을 가진다는 점이 빅로드와 다릅니다.

**빅로드**(우측 위) — 같은 편이 이기면 세로로 쌓고, 편이 바뀌면 새 열을 시작합니다.
세로줄이 길면 그 편이 연속으로 이긴 것입니다. 타이는 새 열을 만들지 않고 초록 사선으로만
표시됩니다.

**파생 로드 3종**(우측 아래) — 빅로드의 패턴이 얼마나 규칙적인지를 빨강/파랑으로 표시합니다.
빨강은 반복, 파랑은 이탈입니다. 모양으로 구분합니다: 빈 링 = 대안목, 채워진 점 = 소로,
대각선 = 갑충로.

> 로드맵에 예측력은 없습니다. 각 라운드는 독립 시행입니다. 플레이어가 실제로 이것을 보고
> 베팅하기 때문에 실제 서비스와 같은 규칙으로 그린 것입니다.

### 다중 테이블 베팅 확인하기

좌상단 ✕를 눌러 로비로 돌아가면, 방금 있던 테이블의 라운드는 **계속 돌고 있습니다.**
목록의 다른 카드도 각자 카운트다운 중입니다.

다른 테이블에 들어가 베팅해 보세요. 두 테이블 모두 정상적으로 정산됩니다.

- 베팅 조작은 **열려 있는 테이블 안에서만** 가능합니다.
- 하지만 닫은 테이블에 남겨둔 베팅은 그 테이블의 딜링 단계가 오면 그대로 집행됩니다.
- 전체 합계가 보유금을 넘으면 "잔액이 부족합니다" 토스트가 뜹니다 —
  잔액 검사는 **전 테이블 미확정 베팅 합계** 기준입니다.

로비 하단 "내 베팅내역" 패널에 지금까지의 베팅이 쌓여 있습니다:

```
[테이블명] #26 뱅커 10,000        +9,500
```

## 7단계: 게임기록 확인

헤더의 시계 아이콘(**게임기록**)을 누릅니다.

**스피드 베팅** 탭에 방금 한 베팅들이 날짜별로 묶여 있습니다. 그룹 헤더에 그날의 베팅 총액과
손익 합계가 나옵니다.

```
2026-08-15                          베팅 45,000 · +14,500
  14:32   VIP-SPEED-03 · 뱅커     10,000    +9,500
  14:31   VIP-SPEED-01 · 플레이어  20,000   -20,000
  14:30   VIP-SPEED-03 · 타이       5,000       푸시
```

> **이 기록은 메모리에만 있습니다.** 새로고침하면 사라집니다. 실제 베팅 데이터는 Firestore의
> `memberLedger`에 안전하게 남아 있지만 이 화면이 그것을 조회하지 않습니다 —
> [G-07](explanation-known-gaps.md#g-07--게임기록이-메모리에만-존재한다) 참고.
>
> 다음 단계에서 진짜 데이터를 확인합니다.

## 8단계: 원장에 실제로 쌓인 것 확인

여기가 이 앱이 목업과 다른 지점입니다.

파트너 어드민 탭으로 돌아가 **회원 관리**에서 로그인에 쓴 회원을 찾아 거래내역을 엽니다.

방금 한 베팅들이 그대로 있습니다:

| `category` | `amount` | `betType` | `staff` |
| --- | --- | --- | --- |
| `bet` | `-10,000` | `banker` | `system` |
| `payout` | `+19,500` | — | `system` |
| `bet` | `-20,000` | `player` | `system` |

규칙 세 가지를 확인하세요:

1. **베팅은 음수, 배당은 양수.** 보유금은 이 값들의 합으로 계산됩니다. 잔액이라는 필드는
   어디에도 저장되지 않습니다.
2. **진 베팅은 `bet` 한 줄만 있습니다.** 배당이 0이면 문서를 쓰지 않기 때문입니다.
3. **타이(푸시)는 두 줄입니다.** `-N`과 `+N`. 순증감은 0이지만 "베팅했고 환불받았다"는 사실이
   원장에 남습니다.

**게임 관리 → 라운드 목록**에서는 방금 돌아간 라운드들이 카드·점수·결과와 함께 저장되어 있는
것을 볼 수 있습니다.

## 9단계: 아바타 모드 맛보기

스피드가 셀프 서비스라면, 아바타는 대리 베팅입니다.

플레이어 탭에서 헤더의 **게임 변경** → **아바타 (AVATAR)**를 누릅니다.

아바타 로비의 카드는 스피드 카드와 **같은 모양**입니다. 다른 점은:

- 카운트다운 자리에 상태 배지가 들어갑니다: `↩ 재입장` / `⏳ 승인 대기` / `✏️ 금일 예약 완료` /
  `🎥 관전`. **비어 있는 테이블에는 아무 배지도 없습니다.**
- 여기서는 라운드가 돌지 않습니다. 신청하고 운영자 승인을 받아야 세션이 시작됩니다.
- 3연속 이상 같은 편이 이긴 테이블에는 🔥 배지가 붙습니다.
- 우측 상단 정렬 드롭다운으로 인기순/오늘 베팅액순/좋은 흐름순/이름순 정렬이 됩니다.

카드를 클릭하면 **읽기 전용 미리보기**가 열립니다. 로드맵과 집계는 전부 보이지만 베팅 패널 자리에
"아바타 신청" 버튼이 있습니다. 라운드 루프도 돌지 않습니다.

전체 대리베팅 사이클(신청 → 승인 → 자동 베팅 → 팁 → 종료)을 실행하려면
[아바타 세션 운영 방법](howto-avatar-session.md)으로 이어가세요. 파트너 어드민에서 승인하는
단계가 필요해 창 두 개를 오가야 합니다.

---

## 만들어 본 것

15분 만에 다음을 했습니다:

- 빌드 없이 정적 파일만으로 카지노 플레이어 사이트를 실행
- 여러 테이블에 걸쳐 베팅하고 실시간으로 결과 확인
- 실제 바카라의 서드카드 룰(푼토 반코 타블로)이 도는 것을 카드로 확인
- 실제 카지노와 같은 로드맵 보드 4종 읽기
- 페어 사이드벳까지 포함한 베팅 스팟 5종 사용
- 그 모든 것이 Firestore에 진짜 문서로 남는 것을 원장에서 확인

**핵심은 마지막 항목입니다.** 게임 결과는 브라우저가 만들어내는 데모지만, 발생한 베팅·배당·라운드는
실제 데이터 모델을 그대로 따르는 문서입니다. 시연 자리에서 어드민을 열어 "방금 그 베팅이 여기
있습니다"를 보여줄 수 있다는 뜻이고, 나중에 결과 생성을 서버로 옮겨도 원장 구조는 그대로 쓸 수
있다는 뜻이기도 합니다.
