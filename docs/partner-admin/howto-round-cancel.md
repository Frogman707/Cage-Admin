# 하우투 — 라운드 취소와 환불

> **분류**: How-to (과제 지향) · **소요**: 약 10분
> **관련 문서**: [화면 58개](reference-screens.md#roundedit-액션) · [알려진 격차](explanation-known-gaps.md) · [앱 레퍼런스](reference-partner-admin-app.md)

딜링 오류나 장비 이상으로 무효가 된 라운드를 취소하고, 걸린 베팅을 전액 환불하고, 지급된
페이아웃을 회수합니다.

**이 작업은 되돌릴 수 없습니다.** 취소 플래그가 한 번 찍히면 같은 라운드를 다시 취소할 수
없고, 환불이 부분적으로만 끝나도 재실행 경로가 없습니다
([P-01](explanation-known-gaps.md#p-01--라운드-취소-환불-루프가-원자적이지-않다)).
시작 전에 아래 사전 조건을 전부 확인하세요.

---

## 사전 조건

- 파트너 어드민에 로그인되어 있음
- 취소할 라운드의 **테이블 ID와 시각**을 알고 있음
- 안정적인 네트워크 — 환불 루프가 중간에 끊기면 일부만 환불됩니다
- 취소 사유가 정해져 있음 (모달의 4개 항목 중 하나)

**먼저 읽어야 할 것**: 실플레이로 만들어진 베팅은 환불되지 않습니다
([P-03](explanation-known-gaps.md#p-03--라운드-취소가-실플레이-베팅을-환불하지-못한다)).
아래 "1. 환불 대상 확인"을 건너뛰지 마세요.

---

## 절차

### 1. 환불 대상 확인 (필수)

취소 버튼을 누르기 **전에** 환불될 베팅이 실제로 조회되는지 확인합니다.

취소 로직은 이 쿼리로 대상을 찾습니다.

```js
db.collection('memberLedger').where('relatedRoundId','==',<rounds 문서 ID>)
```

[Firebase 콘솔](https://console.firebase.google.com/project/cage-admin-25bbf/firestore)에서
직접 확인하는 것이 가장 확실합니다.

1. `rounds` 컬렉션에서 대상 라운드 문서를 찾아 **문서 ID를 복사**합니다.
2. `memberLedger` 컬렉션에서 `relatedRoundId == <복사한 ID>`로 필터합니다.

| 결과 | 의미 | 다음 행동 |
| --- | --- | --- |
| `bet` / `payout` 행이 보임 | 정상. 환불이 동작합니다 | 2단계로 진행 |
| **0건** | ID 불일치. 취소해도 아무도 환불받지 못합니다 | 아래 "환불 대상이 0건일 때"로 |

데모 시드로 만든 라운드는 정상이고, 플레이어 사이트에서 실제로 돌아간 라운드는 0건입니다.

### 2. 라운드 찾기

좌측 **테이블관리 > 게임라운드수정**을 엽니다.

검색창에 테이블 ID를 입력합니다 (예: `HN-A01`). 목록은 시간 내림차순이므로 최근 라운드가
위에 있습니다.

| 열 | 확인할 것 |
| --- | --- |
| 시간 | 문제가 된 라운드의 시각과 일치하는지 |
| 라운드 | 라운드 번호 |
| 결과 | 플레이어 / 뱅커 / 타이 |
| 상태 | `정상`이어야 함. `취소됨`이면 이미 처리된 라운드 |

### 3. 결과만 틀렸다면 — 취소 대신 수정

카드 판독은 맞는데 결과 표기만 틀린 경우, **결과 수정** 버튼이 있습니다.

> **경고**: 결과 수정은 정산을 재계산하지 않습니다
> ([P-14](explanation-known-gaps.md#p-14--라운드-결과-수정이-정산을-재계산하지-않는다)).
> `rounds.result`만 바뀌고 이미 지급된 페이아웃은 그대로입니다. 표시와 잔액이 영구히
> 어긋납니다.

돈이 이미 움직인 라운드라면 **결과 수정을 쓰지 말고 취소를 쓰세요.** 취소 후 정확한 결과로
다시 정산하는 것이 유일하게 정합성이 맞는 경로입니다.

### 4. 취소 실행

행의 **라운드 취소** 버튼을 누릅니다. 모달이 뜹니다.

```
라운드 취소 · a1b2c3d4

이 라운드에 걸린 모든 베팅을 전액 환불하고(지급된 페이아웃은 회수),
라운드를 취소 상태로 표시합니다.

취소 사유  [ 딜링 오류 (카드 뒤집힘/오배당)  ▾ ]
           ☑ 해당 테이블에 인게임공지 등록
```

**취소 사유** 4종:

| 사유 | 쓰는 경우 |
| --- | --- |
| 딜링 오류 (카드 뒤집힘/오배당) | 딜러 실수, 배당 잘못 적용 |
| 엔젤아이 인식 오류 | 카드 스캐너가 잘못 읽음 |
| 장비 이상으로 인한 재셔플 | 슈 이상으로 재셔플 |
| 기타 | 위에 없는 경우 |

이 문자열은 환불 원장의 `memo`와 인게임공지 문구에 그대로 들어갑니다. 나중에 회원 문의가
오면 이게 근거가 되므로 정확한 항목을 고르세요.

**인게임공지 등록** 체크박스는 기본 켜짐입니다. 켜두면 전체 테이블에 노출되는 공지가
자동 등록됩니다.

```
[HN-A01] 라운드 취소 안내: 딜링 오류 (카드 뒤집힘/오배당)로 인해
해당 라운드가 취소되어 베팅이 전액 환불되었습니다.
```

**저장**을 누릅니다. **누른 뒤에는 브라우저 탭을 닫지 마세요.** 환불이 순차 실행되는
동안 창을 닫으면 나머지 회원이 환불받지 못합니다.

"라운드가 취소되고 베팅이 환불되었습니다" 토스트가 뜨면 완료입니다.

## 무엇이 기록되나

```
1) rounds/{roundId}                        ← 트랜잭션 (원자적)
     cancelled: true
     cancelReason: '딜링 오류 (카드 뒤집힘/오배당)'
     cancelledBy: 'admin'
     cancelledAt: '2026-08-14T16:45:00.000Z'

2) memberLedger — 걸린 행 하나당 correction 하나
     bet 행     → {amount: +절댓값, category:'correction', memo:'라운드 취소 환불 (...)'}
     payout 행  → {amount: -절댓값, category:'correction', memo:'라운드 취소 페이아웃 회수 (...)'}
     각각 balanceTotals도 같은 batch에서 증분

3) inGameNotices/{새UUID}                  ← 체크했을 때만
     {text: '[HN-A01] 라운드 취소 안내: ...', tableType:'all', active:true}

4) adminLogs/{새UUID}
     {action: '라운드 취소 (환불 1,250,000, 회수 487,500)', target: <라운드ID>}
```

원본 `bet`·`payout` 행은 **수정되지 않습니다.** 원장은 append-only이므로 상쇄 항목을
추가할 뿐입니다.

## 검증

**1. 관리자 로그의 금액을 먼저 봅니다**

관리자 관리 > 관리자로그, 맨 위 항목.

```
라운드 취소 (환불 1,250,000, 회수 487,500)
```

**환불이 0이면 실패입니다.** 아래 "환불 대상이 0건일 때"로 가세요.

**2. 라운드 상태**

테이블관리 > 게임라운드수정에서 해당 행의 상태가 `취소됨`, 관리 열이 "환불완료"입니다.

**3. 환불 건수 대조**

Firebase 콘솔에서 `memberLedger`를 `relatedRoundId == <라운드ID>`로 필터합니다.

```
category별 건수
  bet         12건   ← 원래 베팅
  payout       5건   ← 원래 페이아웃
  correction  17건   ← 12 + 5. 이 숫자가 맞아야 완전 환불
```

`correction` 건수가 `bet + payout`보다 적으면 환불이 중간에 끊긴 것입니다
([P-01](explanation-known-gaps.md#p-01--라운드-취소-환불-루프가-원자적이지-않다)).
아래 "부분 환불 복구"로 가세요.

**4. 개별 회원 잔액**

계정관리에서 해당 라운드에 베팅한 회원 한 명을 골라 보유금이 베팅액만큼 복구됐는지
확인합니다. 회원 상세 모달의 **입출금** 탭에는 `correction` 항목이 나오지 않습니다 —
그 탭은 `deposit`/`withdraw`만 필터하기 때문입니다. Firebase 콘솔에서 확인하세요.

---

## 환불 대상이 0건일 때

관리자 로그에 "환불 0, 회수 0"이 찍혔다면
[P-03](explanation-known-gaps.md#p-03--라운드-취소가-실플레이-베팅을-환불하지-못한다)입니다.
플레이어 사이트가 베팅과 라운드 문서에 서로 다른 UUID를 쓰기 때문에 조인이 실패합니다.

**라운드는 이미 취소 표시가 됐고, 아무도 환불받지 못했습니다.**

수동 복구 절차:

1. Firebase 콘솔에서 `memberLedger`를 `relatedTableId == <테이블ID>`로 필터하고, 문제 라운드의
   시각 전후 1분 범위에서 `bet` / `payout` 행을 찾습니다. 라운드 주기(아바타 39초 / 스피드
   21초)를 기준으로 어느 라운드에 속하는지 판단합니다.
2. 회원별 베팅액과 페이아웃을 집계합니다.
3. 계정관리에서 회원마다 **+ 추가**(환불) 또는 **− 차감**(페이아웃 회수)으로 상쇄합니다.
   메모에 라운드 ID와 사유를 남기세요.

```
금액: 50000
메모: 라운드 a1b2c3d4 취소 수동 환불 (딜링 오류)
```

이 방식은 `category`가 `correction`이 아니라 `deposit`/`withdraw`로 남습니다. 정산 리포트에서
입금으로 집계되므로, 회계 담당자에게 별도로 알려야 합니다.

**근본 수정**은 플레이어 사이트에서 해야 합니다 —
[avatar-speed G-01](../avatar-speed/explanation-known-gaps.md#g-01--베팅의-relatedroundid가-rounds-문서-id와-일치하지-않는다).

---

## 부분 환불 복구

`correction` 건수가 `bet + payout`보다 적을 때입니다.

라운드는 이미 `cancelled:true`라 취소 버튼을 다시 눌러도 "이미 취소된 라운드입니다"로
중단됩니다. 남은 회원은 수동으로 처리해야 합니다.

1. Firebase 콘솔에서 `memberLedger`를 `relatedRoundId == <라운드ID>`로 필터합니다.
2. `bet`/`payout` 행의 `memberId` 집합과 `correction` 행의 `memberId` 집합을 비교해, 상쇄받지
   못한 회원을 찾습니다.
3. 계정관리에서 그 회원들만 수동 상쇄합니다 (위 "환불 대상이 0건일 때" 3번과 동일).

**예방**: 취소 대상 라운드에 걸린 베팅이 많으면(수십 건 이상) 네트워크가 안정적인 환경에서
실행하고, 완료 토스트가 뜰 때까지 탭을 유지하세요.

## 문제 해결

### "이미 취소된 라운드입니다"가 뜹니다

다른 직원이 먼저 취소했거나, 방금 본인이 더블클릭했습니다. 취소 플래그는 트랜잭션으로
보호되므로 환불이 두 번 일어나지는 않습니다. 관리자 로그에서 실제 처리 내역을 확인하세요.

### 취소했는데 회원이 "환불 안 됐다"고 합니다

순서대로 확인합니다.

1. 관리자 로그의 환불 금액이 0인지 → 0이면 [환불 대상이 0건일 때](#환불-대상이-0건일-때)
2. `correction` 건수가 부족한지 → 부족하면 [부분 환불 복구](#부분-환불-복구)
3. 회원이 보고 있는 화면이 갱신됐는지 → 플레이어 사이트는 새로고침해야 잔액이 반영됩니다

### 인게임공지가 전체 테이블에 뜹니다

의도된 동작입니다. 취소 시 등록되는 공지는 `tableType:'all'`로 하드코딩돼 있습니다
([`app.js:1312`](../../partner-admin/app.js#L1312)). 특정 테이블에만 띄우려면 체크박스를 끄고,
고객센터 > 인게임공지에서 적용 대상을 골라 직접 등록하세요.

### 취소한 라운드가 통계에 계속 잡힙니다

통계 탭은 `rounds.cancelled`를 보지 않습니다. 마켓비율·베팅현황 등 모든 통계가 취소된
라운드를 포함해 계산합니다. 환수율과 승패 비율이 실제와 달라집니다.
