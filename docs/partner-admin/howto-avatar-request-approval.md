# 하우투 — 아바타 대리베팅 승인·종료

> **분류**: How-to (과제 지향) · **소요**: 약 10분
> **관련 문서**: [화면 58개](reference-screens.md#테이블관리-10) · [알려진 격차](explanation-known-gaps.md) · [Avatar 세션 운영](../avatar-speed/howto-avatar-session.md)

회원이 낸 아바타 대리베팅 신청을 승인해 자동 베팅을 시작시키고, 끝났을 때 종료합니다.
승인한 순간부터 회원 돈이 매 라운드 자동으로 나가므로, 종료까지 책임지는 것이 이 작업의
전부입니다.

---

## 사전 조건

- 파트너 어드민에 로그인되어 있음 ([튜토리얼](tutorial-first-approval.md) 1~2단계)
- `tables` 컬렉션에 `type:'avatar'`이고 `status:'open'`인 테이블이 최소 1개
- 회원이 플레이어 사이트(`/avatar/`)에서 신청을 제출한 상태
- 회원 보유금이 지시한 베팅 금액보다 충분함 — **앱은 확인하지 않습니다**

신청이 없으면 직접 만들 수 있습니다. 다른 브라우저에서
`http://localhost:5000/avatar/`에 데모 회원(`0000`)으로 로그인하고, 아바타 테이블을 골라
바이인과 베팅 지시를 넣어 신청합니다. 자세한 절차는
[Avatar 세션 운영](../avatar-speed/howto-avatar-session.md)에 있습니다.

---

## 절차

### 1. 신청 목록 열기

좌측 **테이블관리 > 아바타대리베팅신청**을 클릭합니다.

화면 상단 설명이 계약을 요약합니다.

> 회원이 신청한 대리베팅을 승인(담당 아바타 배정)하면, 승인 기간 동안 매 라운드 지정된
> 베팅이 자동으로 집행됩니다.

상태 필터를 **대기**로 좁힙니다.

| 열 | 확인할 것 |
| --- | --- |
| 신청시간 | 오래된 신청은 회원이 이미 자리를 떴을 수 있음 |
| 회원ID | 승인 전에 보유금을 확인할 대상 |
| 테이블 | `status:'open'`인지 확인 |
| 바이인 | 회원이 걸겠다고 선언한 총액 |
| 베팅지시 | `플레이어 50,000` 형태. 매 라운드 이 금액이 나감 |

이 목록은 실시간입니다. 다른 직원이 처리하면 새로고침 없이 사라집니다.

### 2. 회원 보유금 확인 (승인 전 필수)

**승인 전에 반드시 합니다.** 자동 베팅에는 잔액 검사가 없습니다.

새 탭에서 좌측 **계정관리**를 열고 회원 ID를 검색합니다. 보유금액이 베팅 지시 금액의 몇
배인지 확인하세요.

```
베팅지시 50,000 / 라운드
아바타 라운드 주기 39초 = 시간당 약 92라운드
→ 한 시간이면 최대 460만이 나갑니다
```

보유금이 부족한 상태로 승인하면 잔액이 마이너스로 내려갑니다. 앱이 막지 않습니다.

### 3. 승인하기

신청 행의 **승인** 버튼을 누릅니다. 모달이 뜹니다.

```
아바타 대리베팅 승인
담당 아바타(직원) ID를 입력하면 신청을 승인하고 대리베팅을 시작합니다.

담당 아바타 ID  [ admin ]
```

기본값은 로그인한 직원 ID입니다. 실제로 테이블에 앉아 대리 베팅할 직원이 따로 있으면 그
ID로 바꿉니다. 이 값은 검증되지 않습니다 — `partnerStaff`에 없는 아이디도 그대로 저장됩니다.

**저장**을 누릅니다.

**무엇이 기록되나.**

| 컬렉션 | 내용 |
| --- | --- |
| `avatarRequests/{id}` | `status:'진행중'`, `avatarStaffId`, `approvedAt` |
| `adminLogs` | `action: '아바타 대리베팅 승인 (담당:admin)'`, `target: <신청ID>` |

원장은 쓰지 않습니다. 돈은 플레이어 클라이언트가 라운드마다 씁니다.

### 4. 자동 베팅 동작 확인

플레이어 사이트 탭으로 갑니다. 신청 상태가 `진행중`으로 바뀌고, 다음 베팅 단계부터 지시한
자리에 칩이 자동으로 놓입니다.

파트너 어드민에서 확인하려면 좌측 **회원관리 > 베팅내역**을 열고 회원 ID로 검색합니다.
39초마다 새 행이 올라옵니다.

```
2026-08-14 16:02 | SEH1023 | HN-A01 | — | -50,000
2026-08-14 16:03 | SEH1023 | HN-A01 | — | -50,000
```

**결과 열이 `—`인 것은 정상입니다** —
[P-13](explanation-known-gaps.md#p-13--베팅내역의-결과-열이-실플레이에서-항상-다).
베팅의 `relatedRoundId`가 `rounds` 문서 ID와 달라 조인이 실패합니다.

원장의 `staff` 필드는 `'avatar'`입니다. 스피드 모드 셀프 베팅(`'system'`)과 구분됩니다.

### 5. 종료하기

같은 화면에서 상태 필터를 **진행중**으로 바꿉니다. 해당 행의 **강제 종료**를 누릅니다.

확인 모달 없이 즉시 실행됩니다.

| 컬렉션 | 내용 |
| --- | --- |
| `avatarRequests/{id}` | `status:'종료'`, `endedAt` |
| `adminLogs` | `action: '아바타 대리베팅 강제 종료'` |

플레이어 클라이언트는 다음 라운드 시작 시 `status`를 다시 읽고 자동 베팅을 멈춥니다.
**진행 중인 라운드의 베팅은 취소되지 않습니다** — 이미 원장에 쓰인 뒤입니다.

## 검증

세 곳을 대조하면 세션이 정상 종료됐는지 확실히 알 수 있습니다.

**1. 신청 상태**

테이블관리 > 아바타대리베팅신청, 상태 필터 `종료`. 해당 행의 관리 열이 "종료됨"입니다.

**2. 베팅이 멈췄는지**

회원관리 > 베팅내역에서 회원 ID로 검색합니다. 종료 시각 이후 새 `bet` 행이 없어야 합니다.
1분(라운드 39초의 1.5배) 기다린 뒤 확인하세요.

**3. 관리자 로그**

관리자 관리 > 관리자로그에서 회원이 아니라 **신청 ID**로 대조합니다. 승인과 종료가 쌍으로
남아 있어야 합니다.

```
2026-08-14 16:31 | admin | 아바타 대리베팅 강제 종료 | a1b2c3d4-...
2026-08-14 16:00 | admin | 아바타 대리베팅 승인 (담당:admin) | a1b2c3d4-...
```

**4. 정산**

계정관리에서 회원 보유금을 확인합니다. 시작 시점 대비 차액이
`Σ 베팅 − Σ 페이아웃`과 맞아야 합니다. 회원 상세 모달의 **베팅내역** 탭에서 개별 행을
볼 수 있습니다.

## 신청 거절하기

`대기` 상태 행의 **거절** 버튼입니다. 확인 모달 없이 즉시 실행됩니다.

```js
{status:'종료', endedAt: '<ISO 8601>'}
```

**거절과 강제 종료가 같은 상태를 씁니다.** `avatarRequests`만 봐서는 둘을 구분할 수
없습니다. `adminLogs`의 문구("거절" vs "강제 종료")를 봐야 합니다. 나중에 정산 분쟁이
생기면 이 로그가 유일한 근거이므로, 거절할 때는 회원에게 별도로 사유를 전달해 두세요.

## 문제 해결

### 승인했는데 자동 베팅이 시작되지 않습니다

세 가지를 순서대로 확인합니다.

1. **테이블이 열려 있나.** 테이블관리 > 테이블 관리에서 해당 테이블의 상태가 `운영중`인지
   확인합니다. `마감`이면 플레이어 사이트가 라운드를 돌리지 않습니다.
2. **회원이 그 테이블에 있나.** 플레이어가 다른 테이블로 이동했거나 로그아웃했으면 클라이언트가
   실행되지 않습니다. 대리베팅은 **회원 브라우저에서** 집행됩니다. 회원이 창을 닫으면 멈춥니다.
3. **상태가 실제로 `진행중`인가.** 목록을 새로고침해 확인합니다.

### 종료했는데 베팅이 계속 들어옵니다

플레이어 클라이언트가 다음 라운드 경계에서 상태를 다시 읽습니다. 최대 39초 지연됩니다.
그 이상 계속되면:

- **누군가 다시 승인했을 수 있습니다.** 아바타 승인에는 트랜잭션 가드가 없어, 종료된 신청도
  `진행중`으로 되돌려집니다
  ([P-05](explanation-known-gaps.md#p-05--아바타-신청-승인에는-트랜잭션-가드가-없다)).
  관리자 관리 > 관리자로그에서 종료 이후 승인 기록이 있는지 확인하세요.
- **같은 회원의 다른 신청이 살아 있을 수 있습니다.** 상태 필터를 `진행중`으로 두고 회원 ID로
  검색해 전부 종료합니다.

긴급하다면 테이블관리 > 테이블 관리에서 해당 테이블을 `마감`으로 바꾸는 것이 가장 확실합니다.

### 데이터 초기화 후 유령 신청이 돕니다

`avatarRequests`는 `DEMO_COLLECTIONS`에 없어서 "데이터 초기화"로 지워지지 않습니다
([P-10](explanation-known-gaps.md#p-10--와이프가-balancetotals와-avatarrequests를-남긴다)).
회원은 지워졌는데 `진행중` 신청이 남아 플레이어 클라이언트가 존재하지 않는 회원으로
베팅을 시도합니다.

이 화면에서 남은 `진행중` 항목을 전부 강제 종료하거나, Firebase 콘솔에서 `avatarRequests`
컬렉션을 직접 비웁니다.

### 담당 아바타 ID를 잘못 입력했습니다

수정 기능이 없습니다. 강제 종료 후 다시 승인하면 `avatarStaffId`가 덮어써집니다.
`adminLogs`에는 잘못된 승인 기록도 남으므로, 정산 근거로 쓸 때 주의하세요.
