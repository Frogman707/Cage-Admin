# 아바타 대리베팅 세션을 처음부터 끝까지 운영하는 방법

> **분류**: How-to (과제 지향)
> **소요 시간**: 약 10분
> **관련 문서**: [처리 흐름](explanation-round-flow.md) · [앱 레퍼런스](reference-avatar-app.md) · [알려진 격차](explanation-known-gaps.md)

아바타 테이블을 만들고, 회원이 대리베팅을 신청하고, 운영자가 승인하고, 세션이 돌아가고, 종료하는
전체 사이클을 실행합니다. 끝나면 `memberLedger`에 대리베팅으로 발생한 베팅·배당·팁 항목이 실제로
쌓여 있는 것을 확인합니다.

## 사전 준비

- Firebase 프로젝트에 접근할 수 있고, 앱이 배포되어 있거나 로컬 에뮬레이터가 실행 중이어야 합니다.
  아직이라면 [데모 환경 실행 튜토리얼](../tutorial-run-demo.md)을 먼저 보세요.
- 브라우저 창 **두 개**가 필요합니다. 하나는 파트너 어드민(운영자), 하나는 플레이어 사이트(회원).
  같은 브라우저의 일반 창과 시크릿 창을 쓰면 편합니다.
- 파트너 어드민 로그인 정보 (기본 데모 계정: `admin` / `0000`).
- 로그인 가능한 회원 계정 하나. 없으면 파트너 어드민에서 **데모 데이터 생성**을 실행한 뒤
  유저리스트의 ID를 쓰면 됩니다 (비밀번호 `0000`).

---

## 1단계: 아바타 테이블 확인 또는 생성

파트너 어드민 창에서 좌측 메뉴 **테이블 관리**로 갑니다.

`type`이 `avatar`이고 `status`가 `open`인 테이블이 이미 있으면 이 단계를 건너뛰세요. 플레이어
로비는 이 두 조건을 모두 만족하는 테이블만 표시합니다.

없다면 테이블을 추가합니다:

| 입력 항목 | 값 |
| --- | --- |
| 테이블명 | `AVATAR-DEMO-01` |
| 타입 | `avatar` |
| 카지노 | `HANN` (로비 탭에 있는 값 중 하나) |
| 최소 베팅 | `5000` |
| 최대 베팅 | `1000000` |

저장하면 `tables/{id}` 문서가 `status: 'open'`, `shoeNo: 1`로 생성됩니다.

> **카지노 값 주의**: 로비 카지노 탭은 `HANN` / `NUSTAR` / `SOLAIRE`만 인식합니다. 다른 값을 넣으면
> 테이블이 "전체" 탭에서만 보입니다 —
> [G-08](explanation-known-gaps.md#g-08--카지노-목록이-화면마다-다르다) 참고.

**확인**: 플레이어 사이트에서 아바타 로비를 열면 새 테이블 카드가 보입니다. 아직 라운드가 없으므로
미니 로드 자리에는 "기록 없음"이 표시됩니다.

---

## 2단계: 회원 계정으로 로그인하고 보유금 확인

플레이어 창에서 `/avatar/`를 엽니다.

1. 회원 ID와 비밀번호를 입력하고 **로그인**을 누릅니다.
2. 게임 선택 화면에서 **아바타 (AVATAR)** 카드를 클릭합니다.

헤더의 **보유금** 숫자를 메모해 두세요. 세션이 끝난 뒤 이 값과 비교합니다.

보유금이 0이거나 너무 적으면 파트너 어드민의 **회원 관리 → 보유금 지급**으로 충전하세요.
`category: 'deposit'` 항목이 원장에 추가되고 즉시 반영됩니다.

> 보유금이 부족한 상태로 진행하면 세션이 멈추지 않고 잔액이 음수로 내려갑니다 —
> [G-03](explanation-known-gaps.md#g-03--아바타-자동베팅은-잔액을-확인하지-않는다) 참고.
> 이 하우투에서는 라운드당 베팅액의 최소 10배는 되도록 맞춰두세요.

---

## 3단계: 아바타 대리베팅 신청

1. 아바타 로비에서 1단계의 테이블 카드를 클릭합니다.
   썸네일 오버레이에 **🎭 아바타 신청**이 떠 있을 것입니다.
2. 테이블 화면이 열립니다. 아직 승인 전이므로 **읽기 전용 미리보기**이며, 우측 패널에
   "아바타 신청" 버튼이 있습니다. 이 버튼을 누릅니다.
3. 신청 모달에 입력합니다:

   | 항목 | 예시 값 | 설명 |
   | --- | --- | --- |
   | 바이인 금액 | `100,000` | 기록만 되고 보유금에서 차감되지 않습니다 |
   | 라운드당 베팅 지시 | `뱅커` | `player` / `banker` / `tie` 중 하나 |
   | 라운드당 베팅액 | `10,000` | 매 라운드 이 금액이 자동 집행됩니다 |

4. **신청하기**를 누릅니다.

`avatarRequests/{uuid}` 문서가 `status: '대기'`로 생성되고 로비로 돌아갑니다.

**확인**: 테이블 카드의 오버레이가 **⏳ 승인 대기**로 바뀌었습니다.

> **바이인은 자금 이동이 아닙니다.** 이 값을 원장에 반영하는 코드가 없어, 실제 베팅은 보유금
> 전체를 원천으로 집행됩니다 —
> [G-09](explanation-known-gaps.md#g-09--아바타-바이인이-보유금에-반영되지-않는다) 참고.
>
> **베팅 지시는 세션 중에 바꿀 수 없습니다.** 신중하게 입력하세요.

---

## 4단계: 운영자가 신청을 승인

파트너 어드민 창으로 전환합니다.

1. 좌측 메뉴 **아바타대리베팅신청**을 엽니다.
2. 방금 만든 신청이 `대기` 상태로 목록 맨 위에 있습니다 (`requestedAt` 내림차순 정렬).
   회원ID, 테이블, 바이인, 베팅지시가 입력한 대로 보이는지 확인합니다.
3. 행 우측의 **승인** 버튼을 누릅니다.
4. 담당 아바타(직원) ID를 입력합니다. 현재 로그인한 직원 ID가 기본값으로 채워져 있습니다.
   예: `STAFF01`.
5. 확인을 누릅니다.

문서가 다음과 같이 갱신됩니다:

```js
{ status: '진행중', avatarStaffId: 'STAFF01', approvedAt: '2026-08-12T04:31:00.000Z' }
```

동시에 `adminLogs`에 `아바타 대리베팅 승인 (담당:STAFF01)` 항목이 기록됩니다.

**확인**: 목록의 상태 배지가 초록색 `진행중`으로 바뀌고, 액션 버튼이 **강제 종료**로 바뀝니다.

---

## 5단계: 회원이 세션에 진입

플레이어 창으로 돌아갑니다.

**승인은 실시간으로 전달되지 않습니다.** 회원 화면은 여전히 "⏳ 승인 대기"를 보여줍니다.
갱신하려면:

- 헤더의 **테이블 목록** 버튼을 눌러 로비를 다시 열거나
- 페이지를 새로고침한 뒤 다시 아바타 모드로 들어갑니다.

로비가 다시 로드되면 오버레이가 **↩ 재입장**으로 바뀝니다. 카드를 클릭하세요.

이제 진행중 세션 화면이 열립니다. 미리보기와 달라진 점:

| 요소 | 내용 |
| --- | --- |
| 단계 배너 | `베팅중` → `딜링중` → `플레이어 승`/`뱅커 승`/`타이` 순환 |
| 타이머 링 | 30초부터 카운트다운. 5초 이하에서 강조 표시 |
| 카드 영역 | 딜링 시 P1 → B1 → P2 → B2 순서로 공개 |
| 우측 상태 패널 | 담당 아바타(`STAFF01`), 내 지시, 팁 합계 |
| 채팅 패널 | 같은 테이블 회원들과 대화 |
| 액션 버튼 | 팁 지급 / 슈체인지 요청 / 세션 종료 |

**확인**: 첫 라운드의 딜링 단계에서 "아바타가 뱅커 10,000 베팅했습니다" 토스트가 뜨고, 헤더
보유금이 10,000 줄어듭니다.

---

## 6단계: 라운드가 도는 것을 확인

39초 주기로 라운드가 반복됩니다 (베팅 30초 + 딜링 4초 + 결과 5초).

두세 라운드를 지켜보며 확인할 것:

1. **매 라운드 자동 베팅** — 회원이 아무것도 누르지 않아도 지시 금액이 집행됩니다.
2. **당첨 시 보유금 증가** — 뱅커 승리면 `10,000 × 1.95 = 19,500`이 지급됩니다.
   토스트로 금액이 표시됩니다.
3. **타이는 푸시** — 타이가 나오면 건 금액 10,000이 그대로 돌아옵니다.
4. **로드맵 갱신** — 우측 하단 빅로드에 결과가 하나씩 추가되고, 좌측 비드 플레이트와 P/B/T 집계도
   함께 갱신됩니다.
5. **라운드 번호 증가** — 집계 패널 우상단의 `#1`, `#2`, `#3`…

라운드마다 Firestore에 쌓이는 문서:

| 컬렉션 | 문서 | 조건 |
| --- | --- | --- |
| `memberLedger` | `category: 'bet'`, `amount: -10000`, `staff: 'avatar'` | 매 라운드 |
| `memberLedger` | `category: 'payout'`, `amount: +배당액` | 당첨 시에만 |
| `rounds` | 카드·점수·결과·페어 | 매 라운드 |
| `balanceTotals` | `member_{회원ID}`의 `balance` 증분 | 원장 쓰기마다 (같은 배치) |

---

## 7단계: 팁 지급 (선택)

실제 서비스의 팁 흐름을 확인하려면:

1. 스테이지 우상단의 팁 아이콘 또는 상태 패널의 **팁 지급** 버튼을 누릅니다.
2. 지급 대상을 **아바타** 또는 **딜러**로 고릅니다.
3. 금액(예: `5,000`)을 입력하고 **팁 지급**을 누릅니다.

`memberLedger`에 항목이 하나 추가됩니다:

```js
{
  memberId, casino, amount: -5000,
  category: 'avatar_tip',          // 또는 'dealer_tip'
  relatedRequestId: '{요청 UUID}',  // ← 베팅과 달리 요청 ID가 붙습니다
  relatedTableId: '{테이블 ID}',
  staff: 'member', ...
}
```

**확인**: 상태 패널의 "아바타 팁 합계"가 5,000으로 갱신되고 헤더 보유금이 5,000 줄어듭니다.

팁은 잔액 검사를 거치는 유일한 아바타 모드 자금 이동입니다. 보유금보다 큰 금액을 넣으면 거부됩니다.

---

## 8단계: 세션 종료

두 가지 방법이 있습니다.

### 회원이 종료

상태 패널의 **세션 종료** 버튼을 누릅니다. `avatarRequests` 문서가
`{status: '종료', endedAt}`으로 갱신되고 로비로 돌아갑니다.

### 운영자가 강제 종료

파트너 어드민의 **아바타대리베팅신청** 목록에서 **강제 종료**를 누릅니다. 같은 필드가 갱신되고
`adminLogs`에 `아바타 대리베팅 강제 종료`가 기록됩니다.

**중요**: 운영자가 강제 종료해도 **회원 화면의 라운드 루프는 계속 돕니다.** 회원 클라이언트가
`avatarRequests`를 구독하지 않기 때문입니다. 회원이 로비로 나가거나 새로고침해야 멈춥니다.
운영 절차에서는 강제 종료 후 회원에게 별도로 알려야 합니다.

**확인**: 로비로 돌아오면 해당 테이블 카드의 오버레이가 **✏️ 금일 예약 완료**로 바뀝니다. 오늘은
같은 테이블에 다시 신청할 수 없습니다 (`avatarRequestStateForTable`의 `'full'` 상태).

---

## 9단계: 원장에 남은 기록 확인

파트너 어드민 창에서 확인합니다.

1. **회원 관리 → 해당 회원 → 원장/거래내역**을 엽니다.
2. 방금 세션에서 발생한 항목들이 보여야 합니다:

   | `category` | `amount` | `staff` |
   | --- | --- | --- |
   | `bet` | 음수 | `avatar` |
   | `payout` | 양수 | `system` |
   | `avatar_tip` | 음수 | `member` |

3. **게임 관리 → 라운드 목록**에서 `tableType: 'avatar'`인 새 라운드들을 확인합니다.

`staff: 'avatar'`가 이 베팅이 대리 실행되었음을 나타내는 유일한 표시입니다. 어느 직원이
담당이었는지는 원장이 아니라 `avatarRequests.avatarStaffId`에만 있습니다.

> 베팅 항목의 `relatedRoundId`로 `rounds` 문서를 찾으려 하면 실패합니다. 두 UUID가 별개로
> 생성되기 때문입니다 —
> [G-01](explanation-known-gaps.md#g-01--베팅의-relatedroundid가-rounds-문서-id와-일치하지-않는다) 참고.

## 문제 해결

### 로비에 테이블이 안 보입니다

`tables/{id}` 문서의 두 필드를 확인하세요. 로비 쿼리는 `where('type','==','avatar')`로 가져온 뒤
클라이언트에서 `status === 'open'`을 거릅니다. 둘 중 하나라도 다르면 표시되지 않습니다.

카지노 탭 필터도 확인하세요. 테이블의 `casino` 값이 `HANN`/`NUSTAR`/`SOLAIRE`가 아니면
"전체" 탭에서만 보입니다.

### 승인했는데 회원 화면이 "승인 대기"에서 안 바뀝니다

정상 동작입니다. 회원 클라이언트는 `avatarRequests`를 실시간 구독하지 않습니다. 로비를 다시 열거나
새로고침하세요 (5단계 참고).

### "🎥 관전"이 떠서 신청할 수 없습니다

다른 회원이 같은 테이블에서 진행중 세션을 갖고 있습니다. 클릭하면 읽기 전용 미리보기가 열리며,
그 회원의 세션이 종료될 때까지 신청 버튼이 나타나지 않습니다.

실제로 관전(다른 사람의 라운드를 실시간으로 보는 것)이 되지는 않습니다. 라벨과 동작이 다릅니다.

### "✏️ 금일 예약 완료"가 떠서 신청할 수 없습니다

두 가지 원인이 있습니다.

- **내 요청 때문**: 오늘 이 테이블에서 이미 세션을 열고 종료했습니다. 내일까지 기다리거나 다른
  테이블을 쓰세요.
- **테이블 혼잡 때문**: 오늘 이 테이블의 `진행중`/`종료` 요청이 3건 이상입니다.

시연 중 급하게 풀어야 한다면 파트너 어드민에서 해당 `avatarRequests` 문서의 `requestedAt`을 어제
날짜로 바꾸거나 문서를 삭제하면 됩니다.

### 라운드가 돌지 않고 화면이 멈춰 있습니다

- 브라우저 콘솔에서 오류를 확인하세요. `tableBetVolume`의 `TypeError`가 로비 렌더링을 중단시킬 수
  있습니다
  ([G-06](explanation-known-gaps.md#g-06--tablebetvolume이-timestamp-createdat에서-typeerror를-던진다)).
- 진행중 상태인데 세션 화면 대신 미리보기가 열렸다면 요청 상태를 다시 확인하세요.
  `status`가 정확히 `'진행중'`(한글)이어야 합니다.

### 보유금이 음수가 되었습니다

아바타 자동베팅에 잔액 검사가 없어서 발생합니다
([G-03](explanation-known-gaps.md#g-03--아바타-자동베팅은-잔액을-확인하지-않는다)).
세션을 종료하고, 파트너 어드민에서 `category: 'correction'` 항목으로 보정하거나 보유금을
충전하세요.

### 슈 체인지를 요청했는데 아무 일도 없습니다

정상입니다. `avatarServiceRequests` 컬렉션에 문서는 쌓이지만 이를 읽는 화면이 없습니다
([G-10](explanation-known-gaps.md#g-10--avatarservicerequests에-소비자가-없다)).
